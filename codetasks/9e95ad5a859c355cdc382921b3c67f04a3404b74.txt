Home Connect “program option” entities (the option-backed `number`, `select`, and `switch` entities created from an appliance’s currently available program options) should not permanently disappear just because the appliance temporarily reports a program with no options (or a different set of options).

Update the integration so that, during config entry setup and when appliances connect/pair, option entities are created not only when the corresponding option is present in `appliance.options`, but also when Home Assistant already knows about that entity from a previous run (i.e., it exists in the entity registry for the given platform/domain/unique_id). This allows previously-created option entities to be “restored” into the entity model even if the option is currently missing, in which case the entity should exist but be `unavailable` (and it must not be treated as a restored-state entity via `ATTR_RESTORED`).

The change should apply consistently across Home Connect platforms that use the shared setup helper (e.g., `number.py`, `select.py`, `switch.py`) and must integrate with the existing “dynamic add” behavior when program options become available later. You’ll likely need to adjust the shared setup utilities in `homeassistant/components/home_connect/common.py` so they have access to `hass` and the entity registry when deciding whether to create option entities.
